Bloodborne PC 中文懒人版更新说明

v1.8.6（2026-10-18，账号切换、在线状态与 BBSC 铃铛）
- 一键流程检测到本机保存的申请凭据属于旧联机 ID 时，会为当前 ID 自动重新申请；服务器的 QQ 申请频率和 ID 唯一性限制不变。
- 在线门户新增经申请凭据认证的无缝玩家心跳。传统 shadNet 仍使用 100.64.0.1；BBSC 游戏服务仍使用 100.64.0.2，不改变路由。公共状态合并两种模式、按联机 ID 去重、仅列出同意公开的账号；无缝状态超时自动清除。
- BBSC 启动时复制已存在的 SPRJ0005 存档到临时目录，BBSC_SAVE_DIR 指向此副本，让 BBSC 在游戏运行时备份副本再发放专用铃铛；游戏仍读写原存档，启动器的自动 ZIP 备份保持不变。首次创建角色后需保存并重启无缝模式，才可生成启动前副本。
- 云端须同步更新 portal 容器和 Nginx 配置后，新版启动器的无缝玩家状态上报才会出现在公开列表。

v1.8.5（2026-10-18，在线无缝与联机引导）
- “在线无缝联机”调整到“设置”之后，并显示公共账号服务状态、在线人数和自愿公开的玩家列表；这份列表由两种在线模式共用，不代表当前可加入的无缝世界。
- “局域网联机”改为选择方式、填写账号、注册与检测、启动匹配四步，并提供明确的启动按钮；详细端口与兼容说明移至“帮助”。
- “版本与更新”改用面向玩家的简明更新说明；技术变更仍留在本地完整记录。
- “已知问题”增加缓存排障和显存建议，不自动清理玩家文件。

v1.8.4（2026-10-18，双模式手动排查）
- “在线联机”和“在线无缝联机”都以一键启动为主；只有一键失败时才展开各自页面的手动操作，页面明确标注适用条件与操作顺序。
- 无缝页可直接申请、查询、注册、连接／检测内置私网，并在完成后手动启动 BBSC，无需跳到普通在线页；两个页面共享已保存的账号资料和状态。

v1.8.3（2026-10-18，在线联机手动流程）
- “在线联机”页恢复可见的手动申请、查询、注册、连接／检测内置私网按钮，并注明使用条件与操作顺序；一键启动仍保留。
- 手动注册和私网连接完成后可直接启动传统在线，或返回“在线无缝联机”页启动 BBSC；无缝页新增前往手动流程的入口。
- 将账号与手动操作置于在线玩家列表之前，避免分步按钮藏在首屏下方；详细原理和排障说明仍在“帮助”。

v1.8.2（2026-10-18，在线无缝一键启动）
- 新增“在线无缝联机”页：共用在线账号资料，自动申请／注册、连接内置私网、检查独立 BBSC 服务并启动，无需再到“局域网联机”手动勾选两个实验选项。
- 原“在线联机”页保留传统在线的一键启动，将账号分步操作、私网排查与长篇说明移至“帮助”；传统在线仍使用原服务节点和启动路径。
- QQ 号与联机密码同样使用本机用户加密保存；已填写的在线账号资料在离开输入框、完成申请、保存设置或正常关闭启动器时保留。

v1.8.1（2026-10-18，跨网段诊断版）
- 云端 BBSC 继续使用独立私网服务节点 100.64.0.2；传统在线仍使用 100.64.0.1，两个模式的回环代理和 Docker 数据保持隔离。
- 内置私网桥在有游戏 UDP 流量变化时每 15 秒输出累计发送、接收、拒收、错误计数和最近的私网对端；启动器保存到运行环境 `logs/net-traffic-*.log`，不记录游戏包内容或设备密钥。
- 目前跨网段测试已证实召唤候选可见、召唤请求和 claim 可送达，但客机未完成 JoinRoom；此版用于定位后续私网 UDP/游戏信令环节，不宣称已修复跨网段联机。

v1.7.20（2026-10-17）
- 修复双机均已登录、STUN 已正确登记为独立 100.64/10 地址后仍看不到召唤目标的问题：BBSC 的 HTTP 包装层会把 `summon_messenger` 请求规范到实验服 WebAPI 端口 32315，而覆盖网此前只监听本地 31315，导致请求在玩家电脑上超时、从未抵达服务端。
- 无缝客户端现在同时提供 `127.0.0.3:31315` 状态代理和 `127.0.0.3:32315` BBSC 兼容别名，两者都只转发到隔离节点的尾网 31315；传统在线节点、Docker 映射与 Headscale ACL 均不变。

v1.7.19（2026-10-17）

- 运行脚本现在接受完整的受管覆盖网端口组合，同时继续拒绝局域网中任意主机冒充的 31313/31315 实验地址；32443 游戏 API、32444 中继与主机一致性校验保持不变。

v1.7.18（2026-10-17）

v1.7.17（2026-10-17）
- 为独立 BBSC 无缝实验服增加 Headscale 覆盖网：实验服使用独立服务端节点、独立持久卷与 32313–32444 代理，不复用传统在线服务的节点身份、31313 系列端口或数据卷。
- 修复 Docker 网关会把两位玩家的 STUN 来源都记录成同一 172.x 地址的问题；无缝节点在尾网 UDP 31314 上接收数据并封装经认证的 BBST 来源，再转发到实验容器 32314；客户端 P2P 仍固定使用 31316。
- 无缝节点使用独立 100.64/10 地址和 `127.0.0.3` 客户端回环代理，复用现有 ACL 已允许的端口号，不修改传统节点、`127.0.0.2` 路由或生产 Headscale ACL。
- 在线安装包可同时配置 `overlay_server` 与 `seamless_overlay_server`。只有开启实验性无缝模式时才选择后者；普通在线模式的路由与启动行为不变。
- Windows 无缝服务端首次入网复用现有在线账号流程：读取当前用户由 DPAPI 保护的注册凭据，向门户自动申请十分钟有效、仅使用一次的设备密钥；不再要求玩家复制或粘贴 Headscale 密钥。
- 双机测试包在连接私网时会检测本机回环 32313、32315、32443、32444；四项 Docker 实验服务均已就绪时，当前已注册节点自动兼任无缝发布端。两台电脑可使用同一启动器，未运行实验服务的一端只建立客户端代理；传统在线节点与路由不变。
